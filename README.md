# hyperPattern

Browser-first open-canvas studio for **drafting garment patterns in real units** and **draping them with WebGPU cloth simulation**.

Pattern frames, remesh previews, Transform 3D layouts, and sim viewports live on one pannable board—wired together like a node graph. Designed for indie makers, students, hobbyists, and researchers who want inspectable physics and remixable studies—not a Marvelous Designer / CLO clone.

Product direction and architecture: **[docs/PRD.md](docs/PRD.md)**.

## What you can do

### Canvas project
- Pan the board (Alt-drag empty space) · zoom with ⌘/Ctrl-wheel
- **Right-click empty canvas** to add a node — **New pattern** (a 2D container/frame), **New drape** (3D), a **Note**, or an **Image reference…** — and it lands where you clicked. Right-click a panel on the page instead for the piece menu, which is where **Put selection in container** lives
- Wire **pattern → remesh → transform → drape**; wires show assignments
- Save / load / import projects from the **Projects** modal · undo / redo (⌘Z / ⌘⇧Z)
- Image refs (the **Image reference…** menu entry, paste, or drop) are stored with the project, so they come back on reload. An image whose stored bytes are gone shows a **Re-link image…** button on the node
- Duplicate a node with **⌘D** or **⌥-drag**. Select several (Shift- or ⌘/Ctrl-click a node, or ⌘/Ctrl-drag the board to rectangle-select) and **⌘D** duplicates the set as one group: links between the copies stay between the copies, so a duplicated pattern → remesh → transform → drape is a chain of its own. Duplicating a drape brings the remesh / transform it hides along as copies too, so the new drape drapes the new pattern
- **Backspace / Delete** removes the selected node(s) — no confirmation, undo brings them back · **Esc** clears the selection
- Fullscreen a node (**⛶**); when wired, header **tabs** jump between Pattern / Remesh / Transform / Drape

### Containers
- The canvas is a drawing surface in its own right: the 2D rail is on it, so panels can be drawn, measured and edited straight onto the page with or without a node around them. The page has one drafting scale — canvas units per centimetre — so work on the canvas and work in a container are the same size
- A **2D container** is a **frame** looking at a pattern's centimetre space, the way a Figma frame does — not a window with a zoom of its own. Containers on the canvas are not zoomable: they draw at the canvas scale and pan and zoom with the board
- **Zooming the canvas never changes what the pattern is drawn with.** Outlines, seam allowance, measurements, edge lengths, handles and hit areas are all the same size on screen at 4% as at 400% — the canvas behaves exactly like a full-screen container, which only changes how much of the work you can see. The frame's own label and **⛶** keep their size too: the strip they sit on is counter-scaled against the board's zoom, so the chip stays in the frame's top-left corner and the buttons in its top-right at 4% and at 400% alike. A frame narrower on screen than its own chrome gives up its title — shortened to an ellipsis — rather than letting the buttons wander off its corner
- A frame on the canvas has **no ground of its own**: nothing inside it is opaque, so the page's grid runs straight through it and is *tinted*, not hidden, by the frame's own shading (a 22% veil) — containers read as windows onto the canvas rather than panels pasted on it
- **A frame thins out as the canvas zooms away from it.** Above 2 px to the centimetre (about 31% of the board's zoom, at the drafting scale a new project uses) a container draws everything. Between 2 and 0.9 px/cm it draws **silhouettes**: the panels filled at 45% with their outlines, and none of the marks that would be unreadable at that size — no points, no handles, no edge lengths, no measurement readouts, no seam allowance. Below 0.9 px/cm (about 14%) the fills go too and it draws the panel **outlines** alone. An outline is drawn at every zoom, however far out the canvas is: the marks that thin out are the ones that cannot be read at that size, never the shape of the work itself. Picking any tool other than Move — the pen, Cut, a ruler, a sewing run — brings the whole drawing straight back, so nothing is ever drawn blind; and while a frame is drawing coarsely, a press inside it belongs to the **frame**, so a drag moves the container instead of grabbing a point that is not on screen. Opening a container full screen always draws everything: there, zooming out is a way of looking at the work rather than a way of looking at the canvas
- Move a frame and its work moves with it. **Resize** it by a corner handle, or hold **⌘/Ctrl** and drag any border (the edges only take the pointer while the modifier is down, so a plain drag along the border still belongs to the pattern inside). Either way the frame slides *over* its work — the pieces keep the canvas position they had, so a frame grows outwards and never rescales or shifts what it holds, exactly like a Figma frame. A frame **never** changes its extent to fit the work
- **Clip contents** — the dashed-square button in the frame's chrome, left of **⛶** — hides whatever falls outside the frame without moving it, exactly like Figma's clip contents. Turned off, the work spills over its neighbours and the frame is drawn above them
- **Put selection in container**: pick panels on the canvas, right-click one, and choose it from the piece menu. The run moves into a new frame drawn around it — the pieces are translated into the frame's own space, so nothing moves or changes size on screen
- **Drag whole panels in and out of containers.** Drag a panel off the page and let go over a frame and it becomes that container's work; drag one out past the frame it belongs to and it goes back to the canvas, or onto another frame you drop it on. The panel lands where the pointer let go, and at one drafting scale that means it does not move on screen at all: it simply changes hands, along with its seams and measurements (a seam or measurement left spanning the two sides is dropped, since half a seam means nothing). Work that is only partly picked — a corner being pulled out, a curve handle — stays where it is: only whole panels change hands, and a block moves as a whole or not at all
- Fullscreen a container (**⛶**) to work **beyond its border**: the view pans and zooms freely, the frame is drawn where it sits (a dashed outline), and Clip contents decides whether the overhang is drawn
- The 3D stages — **New drape**, and the remesh / transform inside it — are the 3D containers, and they link to a 2D container by wiring, as before. Piping 3D data back into 2D is still to come
- A 3D container on the canvas keeps its **gnomon** but not its **shading** control: shading is a choice about a viewport you are working *in*, so it is there in full screen and out of the way while you are arranging the canvas
- Each container will carry a **modifier stack** (procedural operations over its pieces, like geometry nodes). The document already reserves the field; nothing reads it yet
- Files saved by earlier versions open unchanged: each frame keeps the view it used to fit, the pieces arrive exactly as they were, and the project gains its canvas pattern on load

### Pattern editor
- Six tools, each with its key on the rail beside its icon — **V** Move, **A** Add, **M** Modify, **C** Cut, **S** Sew, **R** Ruler — and lengths in **cm or inches**. A tool's button does what its key does: it takes its tool up in whatever mode that tool is set to. A tool's *modes* are a row of toggles on the canvas ribbon at the top left, so the mode can be changed without leaving the tool: **A** carries **Pen**, **Rectangle** and **Circle**, with **Block…** and **SVG…** dropdowns beside them that bring the block library and an SVG file in, **M** carries **Extrude**, **Join** and **Bridge** — the fuse and the bridge showing their own 1:1 / many setting beside them — **C** carries the cutters below, **S** carries **1:1** and **Many : many** sewing, and **R** carries the **Ruler** and the **Measure line**, with a **Measurement…** dropdown beside them holding the body-measurement library
- The **bar along the bottom middle** is the tool in hand's own controls, all sharing one slot: what the cut is set to and what it will do next, the two ends of a fuse or a bridge with the button that commits them, and a many-to-many sew run's own settings — which side is being picked and what is on it, **Reverse order**, **Next side** / **Create seams**, **Cancel**
- Cut modes, in the ribbon under **C**: **Line** and **Circle** are drag cutters (**Line** from one end of the cut to the other, **Circle** from its centre out to its radius), **Inset** cuts a smaller copy of the panel under the pointer, sized by where the pointer is inside it, **Curve** cuts along a chain you click down, **Loop** / **Loop straight** preview across the piece from any hovered outline, following the contours between it and the far side or taking the plain chord, and **Dart** cuts a dart into the outline where you click it. Every end of a line and every click of a curve lands on a point or edge under the pointer when there is one, so cuts start on the corner they were aimed at
- **A cut can leave a hole**: a panel is its outline *and* any contours cut out of it, so an inset, or a circle dropped inside a panel, leaves a real opening — the cloth mesh has the hole in it, the hole's edge is an edge of the panel for measuring, seam allowance and sewing, and its points are editable like any others. The bar along the bottom of the viewport carries **Hole** (drop the piece that was cut out) and **Sew pieces** (sew it back into the opening it came from) for every cut that takes one out, and **Sew pieces** for the cuts that leave two halves — which welds them back together along the cut
- Join fuses two pieces along picked edges into one, moving/bending/scaling the first onto the second
- Bridge closes the gap between two pieces — or between two runs of one piece — with new straight edges, leaving the outlines exactly where they are
- Simplify a picked run of points: live reduce/fit preview, seam ends protected
- **Seam allowance**: show the allowance line outside every piece — half an inch by default — and click an edge to give that one its own value, from the ribbon at the top left
- **View**: a typed viewport zoom with **Fit to pattern**, a **lock** that holds the zoom level while you pan, and **hicon projection** — outlines and their measurements in white, the allowance shown, over a grid at double opacity. Inside a container the zoom and the wheel belong to the canvas until the container is opened full screen, because a frame on the board *is* its own view
- Soft snap, multi-select scale, avatar reference overlay, X-ray fill
- Seam bindings become sew constraints after remesh

### Mesh
- Remesh from the linked pattern (structured / Delaunay / centroidal settings in the inspector)

### Transform 3D
- Arrange pieces in space **before** simulating · pose feeds connected sims
- The gizmo's two modes are one key each, the way every 3D package spells them: **W** move, **E** rotate — the button at the bottom left of the viewport shows which is in hand and turns with the same click · **R** turns the selection 90° on the piece's local X

### Sim (drape)
- **Play / Pause / Reset / Rebuild / Snapshot**
- Engines: **CPU mass-spring** or **GPU XPBD**
- Avatar body collision — the generated avatar (from **Avatars**), or the bundled reference body · optional SDF bake/cache under `refPpl/`
- **Strain** map toggle (blue compress · green rest · red stretch)
- **Freeze a piece** — right-click it and choose *Freeze piece*; it holds its current pose while the rest drapes and across rebuilds, with its seams still pulling. Right-click again to *Unfreeze piece*
- **Gathers close onto the seam.** Sew a longer edge to a shorter one and the excess fabric has to fold; under **GPU XPBD** the stitch is solved *after* the fabric's own passes each substep, so the gathered side comes to rest against the seam line rather than hovering short of it
- One active sim at a time; paused sims keep their pose

### Viewport shading (sim + transform)
- The **shading button** in the top-right of a 3D viewport (left of the rotation gnomon) cycles
  **Wireframe** (edges only, no fill, ground and floor hidden) → **Simple** (the plain lit fabric, no
  environment) →
  **PBR** (GGX + image-based lighting, tone mapped), and the caret beside it opens the panel.
- **HDRI background / light probe**: pick any file from `hdri/` (1024×512 `.exr`, decoded in the browser),
  or *None* for a built-in neutral studio gradient. Decoded values are clamped into the half-float range
  before upload — a night HDRI in `hdri/` peaks at 4.2e5, which is 6× what an `rgba16float` texture can
  hold, and storing it as Inf makes the hardware return NaN through every filtered lookup, which shows
  up as the model dissolving into black-and-white static. The chosen map lights the fabric and paints the
  background in PBR mode. The file is a latlong `texture_2d` to every reader: the background unwraps it
  around the camera as a sphere, and the light-probe cubemap is baked from the *same* unwrap once at
  load (`src/render/latlong.ts` holds the single copy of the mapping, and `latlong.test.ts` checks both
  readers against the hardware cube sampling so the probe can never end up lit from the opposite
  hemisphere to the sky you can see).
- In **PBR** the floor becomes a cylinder of the floor's own radius, 12 inches tall, coloured as the
  reference model 25 % darker, and the collision reference mesh (avatar body, or the demo's sphere
  collider) is lit with the same environment instead of the flat shader.
- **Background blur** 50 % by default, 0–100 %, picks a level from a mip chain built once when the
  HDRI loads and samples it through a trilinear filter, so the defocus is continuous rather than a
  handful of repeated ghost taps. One fetch per pixel and the light probe is untouched.
- **Exposure** 0.20×–4.00× scales the HDRI background *and* the PBR shading, keeping the scene and the
  environment on the same stop, plus a **Show background** toggle. Simple and Wireframe never draw the
  environment, so switching modes cannot change how the pattern tools read.
- **Materials** (collapsed section of the same panel): colour, roughness and metallic for the
  **reference model** and the **cloth**. The **pedestal** always takes the reference colour 25 %
  darker — its swatch is read-only — while its roughness/metallic are its own. Colours are stored
  linear (the colour picker converts), so what you pick is what the PBR shader uses.
- Materials live in a shared library that the renderer asks per surface (`forPiece(pieceId)`); every
  piece uses the cloth material today, which is the single seam a future materials node after Remesh
  will use to hand out per-piece materials and textures.
- **Tonemapping** (second collapsed section of the same panel): *Reinhard*, *Uncharted 2*, *ACES*
  (default) or *Lottes* — the four operators from `~/Documents/Dev/pbr-webgpu`, ported verbatim into
  `src/shaders/tonemapping.wgsl`. All four are compiled into the PBR and background shaders and picked
  by an index in the shading uniforms, so switching is a buffer write and a redraw — no pipeline
  rebuild, and the background and the fabric always agree. ACES is the fallback arm of the shader
  switch, so a stored value the shader does not know keeps the original look.
- The mode, HDRI, blur, exposure, tonemapping and materials persist per browser (`localStorage`) and
  apply to every 3D viewport; a new viewport opens in **PBR**, the app's default look, or in whatever
  mode you last chose.

### Split view (2D + 3D at once)
- Open any stage fullscreen and click the **split toggle** between the *Pattern* and *Remesh* chips: the pattern editor fills the left pane and a 3D stage the right.
- The **Remesh / Transform / Drape** chips pick which 3D stage the right pane shows (splitting from a 3D view keeps that view on the right); the pattern stays on the left.
- Editing the pattern tints the 3D viewport's border amber and raises a **“Pattern changed — the 3D build is out of date”** banner just above that viewport's action buttons, with a **Resync 3D** button that remeshes and rebuilds the transforms and sims.
- **Piece selection mirrors both ways**: pick a piece in either pane and it is picked in the other. Leaving split (toggle again, or clicking the *Pattern* chip) returns to the single-node fullscreen.

Pattern viewport: ⌘/Ctrl-wheel (or a plain wheel, or a trackpad scroll) zooms the pattern, the **Zoom** button types an exact percent of the default framing (or steps it 1% at a time), and **Fit to pattern** frames the work; Alt-drag pans inside the editor. **Lock zoom**, in the zoom popover, holds the level where it is — the wheel and the zoom controls stop moving it, while panning stays free.

A frame that is off the canvas is not drawn at all: the board only restates the containers it can see, remembers the ones it skipped, and catches them up the moment they come back into view. Panning across a large canvas therefore costs nothing for the work behind you, and a zoom sweep over a canvas of scattered containers only pays for what is on screen.

Zooming the board is done a frame at a time, not an event at a time: a trackpad sends several wheel events per frame, and each one used to restate every container and the page in full — with three or four forced layouts of its own — so a fast two-finger zoom could cost more than a frame's budget per event. The events now gather and compose into a single pass per frame (exactly the same zoom, since the steps multiply), and the frames let their chrome *trail* while the board is moving, catching up in one repaint when it settles: only the size of the chrome depends on the zoom, never the geometry. A twenty-four-step sweep therefore repaints each container about ten times rather than twenty-four, and a pan — which changes no frame's own scale at all — touches none of them.

Zooming, on the canvas and in a container alike, only ever changes *how much* of the work is on screen. Every fixed-size thing the editor draws — outline weights, seam allowance, ruler and measurement readouts, edge lengths, points and handles, the rotate ring, the click radius that decides what a press lands on — is computed from the editor's own screen scale, so it comes out the same number of pixels whatever the zoom. Zooming the board out to 4% shows more of the canvas at hairline-thin *geometry*, not hairline-thin *lines*: a piece drawn 2 px wide at 100% is still 2 px wide at 4%, and its edge labels are still 11 px and still legible. That is the same rule a full-screen container follows, and the two are the same code: a frame on the canvas tells its editor how far the board is scaling it, and the editor divides its chrome by that. The frame's *own* label and clip button are canvas chrome rather than pattern chrome, and they hold their size the same way: the strip they sit on is laid out against the board's zoom and scaled by its inverse, so the chip is the same 12px type in the frame's top-left corner at any zoom and the buttons stay in its top-right — the title shortens to an ellipsis when the frame is smaller on screen than its own chrome, which is what keeps a zoomed-out canvas readable instead of covered in overlapping labels.

Cut's modes, in detail: they are toggles on the canvas ribbon at the top left, not rows in a rail menu, because the mode *is* the cut's setting and changing it is something you do while looking at the piece you are about to cut. **C**, or the **Cut** button, puts the cut in hand in whatever mode it is set to, and the rail's own tip names it ("Cut · Loop straight — hover an edge to run straight across"). Switching modes mid-session drops any draft in hand — a half-clicked chain belongs to the cutter that was drawing it. Add's modes work the same way: the ribbon beside the canvas picks the shape, and **A** brings the tool up in what it is set to.

The drag cutters, in detail: **Line** and **Circle** each work with a press and a release, and both take their aim from the outline. A line cut runs from where the press landed to where it was released; either end that lands near an outline point or edge is taken from there, so a cut can be run from corner to corner without the end sitting a few pixels off the corner you clicked. Shift locks the angle instead, and then the end is the release point: the preview shows which of the two the cut is going to do. The panel a line cut is for is the one the drag itself runs through — the panel between the press and the pointer, measured by how much of the drag lies inside it — and never one the line's own direction happens to reach *behind* the press, so a cut drawn away from a panel leaves that panel alone however squarely it is pointed at. Within its panel the cut is the whole line through the two points, reaching the outline on both sides — which is what the drawn preview shows, and how a cut started in the middle of a panel still runs edge to edge. A circle is set down where the press lands and sized by the drag — the centre stays on the spot it was placed at however far the rim is dragged out, and Shift quantises the radius to half a centimetre — and the release cuts. What it cuts along is the part of the rim *inside* the panel: a circle dropped over an edge trims an arc out of that edge, and one taking a bite out of an edge is cut around its long way, the side that stays in the panel. So a circle whose centre sits outside the panel is not a circle that misses it: the rim crossing the edge is the cut. A circle lying wholly *inside* the panel is cut out of it — an opening in the panel with the disc that came out of it as a piece of its own, which is what the **Hole** and **Sew pieces** toggles are for; one lying wholly *outside* it crosses the outline nowhere and separates nothing, and is refused rather than left in two. Two crossings on one edge — a shallow arc trimmed from a straight edge, an edge bowed out and back — cut as readily as any other, both cut points landing on the outline exactly where the preview drew them.

The inset and the hole, in detail: **Inset** cuts along a *smaller copy* of the panel under the pointer — the same shape, scaled down about the panel's own centre of area, which is the difference that makes an inset read as an inset rather than as a line held a fixed distance from the edge. A uniform offset cannot help changing the proportions: take 2 cm off every side of a 40 × 20 panel and what is left is 36 × 16, no longer that panel's shape at all, and off a bend that tightens the line goes wrong relative to its neighbours. A scaled copy keeps every proportion and every ratio of curvature exactly — a round panel gives a round loop to well under a hundredth of a millimetre, a 2:1 panel gives a smaller 2:1 panel, and a shaped edge keeps its shape — so the loop always looks like the piece it was cut from, a little way inside it. It is exact rather than near, too: scaling a cubic's anchors and handles about a point scales the whole curve about that point, so nothing is approximated and nothing drifts as the loop gets smaller.

The pointer sets the size: the loop is drawn through the point you are hovering, so pushing the pointer in from the edge shrinks the copy and pulling it back out grows it, the way you would size a facing by eye. The bar reads both numbers that matter — the size the copy keeps, as a percentage of the panel, and how far inside the edge it runs at its tightest, which is the depth you would cut a facing to; Shift quantises the size to a whole percent so the same loop can be asked for twice. A loop with no room for it is simply not offered: not inside the panel at all, right on its edge where the copy would be the panel itself, or so deep that the copy would run through a hole already cut in the piece — and the bar keeps saying where to hover.

Cutting a loop out of a panel leaves two things, and what becomes of the second is the toggles in the cut bar. The panel keeps every point it had and gains the loop as a **hole**: its cloth is now the panel less what was cut out, the mesh leaves the opening empty — a drape hangs around it, not across it — and the loop's own edges belong to the panel, so they are measured, allowed for and sewn like any other edge, and its points are edited like any other points. The piece that came out of the hole is a piece in its own right: left lying in the opening by default, sewn back into it all the way round by **Sew pieces** (which is how a lining, a facing or a bound opening is drafted), or dropped altogether by **Hole**, which leaves the opening as a hole and nothing else. The same cut, and the same two toggles, come with a circle dragged inside a panel — the gesture for punching a hole — and **Sew pieces** on a cut that leaves two *halves* rather than a loop welds them back together along the cut, which is how a piece is cut for drafting while the cloth stays whole. A panel that already has a hole is not something the cut will take it again, or fuse or bridge: those all work from a single closed outline, and the bar says so rather than quietly handing back a piece with its hole lost. Cut first, then punch.

Curve cut, in detail: click points down the way the pen draws them, and the chain through them is the cut. The panel it cuts is the one the chain is *drawn through* — the one it spends most of itself inside — so a cut never takes a panel beyond the end of the chain, or before its beginning, however the ends are carried on. Each end is carried out to that panel's outline along the direction the chain was going, drawn faintly and stopping at the edge, so a cut started in the middle still runs edge to edge instead of refusing to leave the inside; clicks that land near a point or an edge snap onto it, so a cut can be started exactly on a corner. **Fit** decides how the clicks are joined: **Smooth** bends through them, each point carrying one tangent read from its neighbours, and **Straight** joins them with plain edges. The bar names the panel the cut will take and how it will leave it — "Cuts Front panel A in two", "The cut has to cross … twice" — and **Done** is only offered when the cut really does cross the outline twice with panel left on both sides. **Sew split** welds the two halves back together along the cut: the cut's own edges are sewn to each other, so a piece can be divided for drafting — grainlines, seam allowance, a panel that is really two — while the cloth stays whole on the stand. Done commits as one undo step; Cancel, Escape or a right-click throws the draft away. ⌘/Ctrl+Z puts a cut back.

Join, in detail: pick the edges to fuse — one edge each, or whole runs with **Many : many** in the ribbon — and the first piece picked is brought onto the second: **Move & scale**, the default, moves, turns and rescales the whole piece until its edges match the other's within the **Tolerance**, filling whatever is left between the two chains the way a bridge fills between two runs, and **Warp** bends, stretches and turns it until the edges lie exactly on the other's. Many mode is many-to-many: each side takes a run of whole edges, the runs need not have the same number of edges or the same lengths, and each run is read off the outline in the order it was picked; **Confirm edges →** (or Enter) hands the picking over to the second piece — the button then reads **← First side** and hands it back, so either run can still be added to — which decides where a click on a *shared* boundary — two pieces laid along the same edge, or the two halves a cut left behind — belongs: before the hand-over such a click is the moving piece's, so a run along the shared edge can be picked, and after it the click is the second piece's. Warp's deform is a ribbon map: every point of the moving piece keeps its distance *along* its picked edges (as a share of their length) and its perpendicular offset, so the picked edges land exactly on the other piece's, the piece stretches along them by the ratio of their lengths, and the rest follows and bends with them. Points and handles both move, so a curve drawn into the moving piece keeps its shape and picks up the other piece's contour. Which way round the two chains meet is not asked of you: there are only two ways two outlines can share one boundary, and the one whose fused outline holds both pieces' area and keeps the moved piece whole is the one taken. Edges of the moving piece that had been sewn keep their seams — they are read at the point they became after the fuse — and so do seams on the second piece; seams along the two fused chains belonged to edges that no longer exist and go with them. A run that turns a corner harder than the piece is deep cannot be brought round without folding, and a fold is not a fuse: the bar says so and refuses ("pick a shorter run, or one that turns the same way") rather than hand back an outline the two pieces have been mangled into. The bar says what the fuse would do — which piece moves onto which, and *why not* when it cannot ("Those edges are not next to each other", "That join would fold the pieces onto each other") — and the outline it would make is ghosted in the viewport before anything is committed. **Fuse pieces** commits it as one undo step: the two pieces become one, keeping the second piece's name, and ⌘/Ctrl+Z puts them back.

Bridge, in detail: both runs may be on one piece, which is how a bay or a notch is filled: the two runs leave two arcs of its outline between them, a single straight edge is drawn across one of them, and the other arc goes interior with the runs, so the piece grows to hold what lay between them. Which arc that is depends on which way the runs face each other, so both are tried and the one that leaves the piece *bigger* than it was is the fill — the other is always just a cut-off piece of the outline, never a fill — and runs with no bay between them (a panel's bottom edge and its top edge, say) are refused with the reason. A bridge is otherwise a fuse where nothing moves. Pick the edges to span — one edge each with **Bridge · One edge each**, or whole runs with **Bridge · Edge runs (many)**, picked side at a time with **Confirm edges →** just as a join is — and the two picked runs are closed by a straight edge at each end, so the area in between becomes part of one piece with them. Every anchor and handle of both outlines comes through unchanged, and at the four joints the handles that used to run along the picked edges are squared off, because a bridge is a straight line where those edges were; the picked edges themselves are interior now and drop out of the outline. Which of the two runs meets which end of the other is not asked of you: as with a fuse there are only two ways round, both are tried, and the one whose outline does not cross itself is taken, whichever way the second piece happens to be wound. Bridging the two halves a cut left gives the panel they were cut from, with the joints that landed on the same spot folded into single vertices — seams that named them are read at the point they became. A bridge between runs that face away from each other, or to a piece that is already on top of another, would have to double the outline back on itself, and is refused with the reason rather than handed over as a shape nothing can be cut from ("That bridge would cross itself — pick runs that face each other"). The outline it would make is ghosted in the viewport first, and **Bridge pieces** commits it as one undo step, keeping the second piece's name; ⌘/Ctrl+Z puts both pieces back.

Loop cut, in detail: the cut enters square to the edge under the pointer and crosses the piece. **Loop (follow)** — the default — holds the pointer's own share of the way between the piece's two contours as it steps across, so a panel with parallel sides cuts straight, one whose sides curve together bends with them, and a tapering panel gets an evenly spaced cut. The walls it measures that share against are the contours *the cut runs between* — the ones roughly parallel to it — read at each step around where the cut already is, so a cut cannot be dragged outwards along the edge it is about to end on, or around a corner to a wall it should never have seen. It ends where it meets the boundary, which is usually the far side of the piece but not always: across a panel that tapers away, the cut is still on the panel after the edge normal has left it, and the trace follows it out to the edge it actually reaches. Slides sideways are capped and the traced line is faired, which keeps corners and notches in the outline as turns rather than spikes. **Loop (straight)** takes the plain chord. Either way the result is an ordinary cut: the piece splits, its seams remap, and ⌘/Ctrl+Z puts it back.

Undo / Redo restores the document only — views never move: 3D camera, 2D pattern zoom/pan, and the board's own pan/zoom all stay put.

Seam allowance, in detail: it is the fabric left *outside* the seam line, so it is drawn as its own dashed line and never touches the pattern's geometry — the mesh, the sewing and the drape all stay on the seam line, and editing an allowance does not make the 3D build stale. A piece carries one allowance for all of its edges and any number of per-edge overrides; the standard half inch (1.27 cm) is what an untouched piece uses, so nothing is written into the document until you actually change something. Overrides are keyed by the id of the point an edge starts at, which is the edge's identity, so they survive inserts and deletes elsewhere on the piece, travel with a piece that is duplicated or mirrored, and are kept when a drafted block regenerates its outline (its ids come back the same every time). The line itself is a mitred offset of every edge by its own value, which is why a change of allowance at a corner reads as a step: the edge with no allowance sits on the seam line, and the outline steps out to meet the rest. Smaller values shrink it, 0 puts it back on the seam line, and 10 cm is the ceiling.

Measuring, in detail: the **Ruler** tool carries two modes, because they answer different questions — a **Ruler** is a real rule laid over the work, its length a *person's* body measurement, picked from the **Measurement…** dropdown on the ruler's own ribbon, while a **Measure line** reads the pattern itself. A measurement is a list of things to read, and its value is their sum: an edge contributes its arc length, and two points contribute the distance between them, so picking three edges gives you the run's total and picking two points gives you the gap. Points chain in the order you pick them, which means a third pick carries the walk on rather than starting again, and a pick waiting for a partner is held as a session pick — a measurement never contains half a span. Overlaying a run of edges and reading one number is what the hover highlight is for: the value says how much, the highlight says of what.

Totalling measurements, in detail: **Shift-click** readouts with the measure tool in hand to gather them. The bar then says how many and what they come to, and **Sum** adds one more measurement that reads all of their items — so the total is the number you would get by adding the readouts up, and it stays live against the pattern because the items name pieces and edges rather than coordinates. The gathered measurements are left exactly as they are: the sum is a fourth measurement beside them, drawn with its parts dimmed and its readout tagged "sum of 3", which can be moved, hovered and deleted like any other. It copies their items rather than pointing at them, so a later pick added to one of the parts does not follow through into the total — re-gather and sum again for that.

The measure line, in detail: dragging across the work is left-to-right on a technical drawing, but here it cuts the piece wherever you draw it. Every place the line crosses an outline becomes a measure point, and what is measured is the stretch of the line that lies *inside* a piece — entry to exit. That is why a line drawn right across a panel reads its width along that diagonal, why one drawn across two panels reads both of them and adds them, and why the empty canvas *between* pieces is measured by neither: only the work is measured, never the space around it. A line that misses the work, or only grazes one edge, makes nothing at all, and one that starts inside a piece has entered before the drag began, so the first crossing it meets is the way out and that piece contributes nothing (start outside to read it). A measure point is **not a control point**: it is stored as a fraction along the edge it landed on, and resolved through the piece every time it is drawn or measured. That is what makes it ride the outline — drag an edge's points around and the measure point stays at the same share of the way along it, so one placed in the middle of an edge is still in the middle of the reshaped edge, and it moves not at all when a *different* edge is edited. It costs nothing to remove for the same reason: deleting a measurement leaves the piece exactly as it was. The one thing it cannot survive is its edge being split in two, because the edge it named is gone; the measurement then says it is incomplete rather than reading a number that is no longer true. Like rulers, measurements are drafting references — they round-trip with the project and never leave a mesh stale.

Simplify points, in detail: hand-drawn curves arrive with dozens of anchors where the shape needs five, and a piece you have to edit point by point is easier to work with after they are thinned. Pick a run of points and the reduction is previewed live in the viewport — the outline really is rewritten as **Reduce** moves, so you are looking at the piece, not a sketch of it — and the bar says how many points are left ("24 → 9 points"), counting runs when the picks were not all in one stretch. **Reduce** is a share of the picked points: 0% keeps them all, 100% keeps the two that end the run (fewer, if the shape is simple enough to collapse). **Fit** decides what happens between the survivors: **Corner** draws straight edges; **Smooth** keeps the tangent the outline was drawn with at each survivor, reaching a third of the way to the next one, so a curve drawn through the run stays a curve and a corner stays a corner instead of being rounded off — the default matches what the run already was. **Done** commits it as one undo step; **Cancel**, Escape, or any fresh gesture on the canvas puts the points back. Nothing outside the run moves — not the neighbouring anchors, and not their handles, which belong to the edge before the run. Seam and dart ends are held onto whatever the reduction is asked for: a seam is an *edge* between two points, so dropping one of its ends would leave the stitching pointing at an outline that no longer has that edge.

Gathers, in detail: a gather is one edge sewn to a shorter one — a skirt's 61 cm waist onto a bodice's 40 cm — so the excess has to fold. The stitch pairs the two edges by *how far along* they are, not by distance: the same share of the way along each side, evenly spread over however many samples the shorter side has, which is what leaves the longer side with spare length to pucker into folds. On the stand, the gathered edge is a hard constraint, and in **GPU XPBD** it has to be solved last to stay one: every substep runs stretch, bend and the strain limiter for the fabric, and the stitch's own passes *after* them, because the fabric's passes push a gathered pair apart again as the material travels into its folds. While a seam is still wrapping it may only close a small slice of its travel budget per pass — that is what stops a stitch slamming through the body on the way over — but once it is closed it projects at full strength with a whole substep's budget, and the pair comes to rest at the seam's own gap (0.15 cm by default) instead of hovering short of it. What is left after that is the fabric's own reluctance: on a 40 cm to 61.7 cm gather, floppy bending settles around 1.8 mm and stiff bending around 2–3 mm, while stretch stiffness barely moves the number — it changes how deep the folds are, not whether the fabric meets the seam. The CPU mass-spring engine keeps its own seam springs, which pull the pair together over `SEAM_RAMP_SECONDS` instead.

## Notes

- Canonical units are **centimeters**; the **Units** button on the toolbar opens a popover to switch the display to inches. The change is document data, so every canvas follows it and the project file records it.
- The studio toolbar is icons only: **New**, **Projects**, project name, **Undo / Redo**, **Avatars** (the person icon), **Units**. Each carries its label as a tooltip. Nodes are added from the canvas — right-click empty board.
- A boarded node draws its title and **⛶** over the top of its own viewport rather than in a bar above it, so the preview gets the whole rectangle. The strip between them is transparent: dragging a node on the board is done by its title chip, and a gesture in that top band still reaches the viewport underneath. Both keep their size on screen however far the board is zoomed.
- A **Note** has no bar at all. It is a rectangle of text you can type in, and it is dragged by the **12px border** around it — an invisible band inside the note's edge, sized on screen so it stays 12px however far you are zoomed out (and gives way to a quarter of the note when the whole note is smaller than that, so there is always somewhere to type). A press in the middle of a note lands in the text, where the caret belongs; a press within 12px of the edge picks the note up, so a drag on the border moves it and ⌫ deletes it
- Loading a **custom avatar model** (your own OBJ / SDF) is off the toolbar for now; avatars come from **Avatars** (measurements → generated model).
- Type is **IBM Plex Sans** throughout, with **IBM Plex Mono** for anything read as a number, a code or a key; both are pulled from Google Fonts in [`index.html`](index.html).
- Rebuild the mesh (and sim) after pattern or sew changes so topology stays in sync.
- The canvas and every container share one drafting scale (`canvas.draftScale`, canvas units per centimetre). A container's frame carries the rest of its view — `cmScale`, the centimetre point at its top-left corner, and `clip` — so a board of containered patterns still measures and reads at the canvas's own size.
- Avatar SDF baking can write into `refPpl/` via the Vite dev API so you don’t rebake every session.

Legacy WebGPU cloth demos and GIFs from the earlier drop/wind playground remain available via [`demo.html`](demo.html).
